# lri-mono

Достаёт монохромные кадры из контейнера `.lri`, который L16 пишет рядом с JPEG.

Внутри `.lri` лежат планы всех модулей, участвовавших в снимке, — упакованные
10 бит, по одному на модуль. Два модуля из шестнадцати, **A2** и **C6**, несут
AR1335 **без цветофильтров**: их план уже панхроматический, без дебайеризации и
интерполяции, полные 4160×3120. Остальным четырнадцати нужен один из CFA-методов.

Разбор контейнера — на [lri-rs](https://github.com/gennyble/lri-rs), зафиксирован
по ревизии в `Cargo.toml`.

## Сборка и запуск

```
cargo build --release
./target/release/lri-mono L16_00115.lri --out ./out
```

По умолчанию для монохромного модуля пишется `native`, для цветных — `bin`.

## Методы

| Метод | Что делает | Размер |
| --- | --- | --- |
| `native` | план как его считал сенсор. Только для A2 и C6 | 4160×3120 |
| `bayer` | цветной план в серый без нормировки каналов; сетка видна диагональным переплетением — это фиксированный узор с периодом 2 px, не зерно | 4160×3120 |
| `bin` | квад 2×2 усредняется в один панхроматический отсчёт; СКО шума вдвое ниже, это ровно один стоп | 2080×1560 |
| `r`, `b` | одна фаза сетки: красный — тёмное небо и фарфоровая кожа, синий — ортохром | 2080×1560 |
| `g` | зелёные отсчёты плюс заполнение дыр по четырём ортогональным соседям; полный размер с квинконса, так что по диагоналям мягче, чем по числу пикселей | 4160×3120 |

Работа идёт по линейным значениям с вычтенным чёрным, кривая накладывается в
самом конце — `--linear` отдаёт линейные 16 бит, годные для стекинга и замеров.

## Ключи

```
--out DIR        куда складывать PNG
--methods LIST   native,bayer,bin,r,g,b или all
--modules LIST   A2,C6,…  (по умолчанию все, что есть в файле)
--black N        уровень чёрного, по умолчанию 42 — из самого контейнера
--white N        насыщение, по умолчанию 1023
--linear         без sRGB-кривой
--stretch        белая точка по 99.9-му перцентилю, а не по насыщению
--stats          числа по каждому модулю плюс тест сетки
--census         опись: сенсор, мозаика, собранный свет, колориметрия, экспозиция
--peek CAM       прочитать только план этого модуля вместо всего файла
--device PATH    брать файл прямо с камеры по adb
--calib          заводская калибровка: геометрия, зеркала, интринсики по модулям
--hotpixels      разбор `hotpixel.rec` — карты дефектов по модулям
--fingerprint    определить, с какой камеры кадр (по заводской геометрии)
--raw            выгрузить сырые отсчёты сенсора 16 бит little-endian
```

## Точечное чтение

Снимок весит 160–230 МБ, потому что несёт планы всех участвовавших модулей; один план —
16 МБ. Заголовки блоков позволяют не читать остальное:

```
lri-mono --peek A2 --device /sdcard/DCIM/Camera/L16_00145.lri --out ./out
→ 16.2 МБ из 163 МБ, 13.6 с, результат побайтово равен полному разбору
```

Инструмент обходит блоки по 32-байтным заголовкам, разбирает их протобуф-сообщения,
печатает опись всех модулей — размер, мозаика, смещение, выдержка, усиление — и качает
ровно один нужный диапазон. У toybox на камере `head` не понимает `-c`, поэтому диапазон
режется через `dd` с выравниванием по блокам и подрезкой на стороне компьютера.

## Тест сетки (`--stats`)

Отвечает на вопрос «монохромный ли сенсор» по данным, а не по метке в файле.
Для каждого тайла 64×64 считаются средние по четырём фазам 2×2 и берётся размах,
нормированный на уровень тайла. У цветного сенсора любой цветной участок кадра
даёт огромный размах, у панхроматического остаётся только шум:

```
A1  Ar1335      tiled CFA test: median 67.7%  p95 83.2%
A2  Ar1335Mono  tiled CFA test: median  1.2%  p95  4.0%
C6  Ar1335Mono  tiled CFA test: median  1.2%  p95  3.5%
```

Общими средними по кадру такой тест обмануть можно — нейтральная сцена усредняет
каналы. Потайловый — нет.

## Чёрный: 42 или 64

Контейнер в своей `SensorCharacterization` объявляет `black=42 white=1023`,
а Camera2 на устройстве отдаёт `blackLevelPattern = 64` для логической камеры.
По умолчанию берётся значение контейнера — оно описывает конкретно этот план.

## Отпечаток камеры (`--fingerprint`)

Кадр называет свою камеру сам: `LightHeader` несёт `device_unique_id_low` и
`device_unique_id_high`, склейка которых в шестнадцатеричном виде совпадает с `uuid.txt`
раздела `/lightcal`. Ключ печатает его первым.

Второй строкой идёт хэш заводской геометрии — независимая проверка: она поштучная, между
нашими двумя камерами интринсики расходятся в среднем на 160 px. Метку можно подделать
или потерять, геометрию — нет.

```
lri-mono L16_00087.lri --fingerprint
L16_00087.lri: camera fingerprint 70a9606d58c6035a  (16 modules)
```

Тот же хэш выдаёт и `calibration.lri` самой камеры, так что архив осиротевших кадров
раскладывается по камерам и связывается с нужным набором калибровки.

## Сырые отсчёты (`--raw`)

`--raw` пишет план как есть: 16 бит little-endian, ширина × высота, без вычитания
чёрного, без масштабирования и без кривой. Это то, что нужно стекингу и работе с
дефектами; PNG для таких задач — уже интерпретация.
